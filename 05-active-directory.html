⚙️ Pre-Engagement Setup — Do This FirstSTART HERE

1. Set engagement variables (run this FIRST)

variable exports — paste with values filled in
required
What this does: Sets all the shell variables every command in this file uses. Fill in the values from your nmap/recon. Re-run at the start of every engagement.

export DC_IP=10.0.0.10           # DC IP (often same as $IP)
export DOMAIN=corp.local         # lowercase domain
export REALM=CORP.LOCAL          # UPPERCASE for Kerberos

# Your machine =============================================
export KALI=$(ip -4 addr show tun0 2>/dev/null | grep -oP '(?<=inet\s)\d+(\.\d+){3}')

echo "export IP=..." > ~/engage.env then source ~/engage.env

2. Add the DC to /etc/hosts

/etc/hosts entry — Kerberos requires FQDN, not IP
required
Why: Kerberos binds tickets to SPNs that include the hostname. Using IP gets KDC_ERR_C_PRINCIPAL_UNKNOWN even with correct creds. Add DC + domain + short alias all in one line.
# One-shot add (uses your $DC_IP, $DC_HOST, $DOMAIN variables):
echo "$DC_IP $DC_HOST $DOMAIN $(echo $DC_HOST | cut -d. -f1)" | sudo tee -a /etc/hosts
# Adds:   10.0.0.10  dc01.corp.local  corp.local  dc01

# Verify both lookups work:
nslookup $DC_HOST
nslookup $DOMAIN
getent hosts $DC_HOST

# Shortcut alias (from install-ad-tools.sh):
dc-host $DC_IP $DC_HOST

# When pivoting — add each new host as you find them:
echo "10.0.0.15 ws01.corp.local ws01" | sudo tee -a /etc/hosts

clock sync — only if Kerberos errors out
When to bother: only if a Kerberos command returns KRB_AP_ERR_SKEW or KDC_ERR_PREAUTH_FAILED with verified-correct creds. Most labs are fine without syncing. Check skew first.
# Check skew (compare your time to DC time):

# Option 3 — ntpdig (always available on Kali via sntp pkg):

# Option 4 — chrony if running:

4. Configure /etc/krb5.conf (only if needed)

Did you leave the krb5-user install prompt blank? That was correct. You're a pentester switching domains every engagement, not a domain user. Configure per-engagement using the template below.
do I need krb5.conf?
Don't need it: impacket-* tools, certipy, kerbrute, evil-winrm, nxc — these accept realm via flags.

Do need it: running kinit directly, PKINIT cert auth flows, some tools that internally call libkrb5.
# Quick test — run a Kerberos command. If it works, you don't need krb5.conf:
impacket-getTGT "$DOMAIN/$USER:$PASS" -dc-ip $DC_IP

# If "kinit: Cannot find KDC" → configure krb5.conf:
sudo cp /etc/krb5.conf.template /etc/krb5.conf
sudo nano /etc/krb5.conf
# Replace CORP.LOCAL with $REALM, dc01.corp.local with $DC_HOST

# Shortcut alias:
krb-template
krb5.conf — minimal working template
What this does: Writes a minimal krb5.conf using your variables. Run after setting $REALM and $DC_HOST.
sudo tee /etc/krb5.conf > /dev/null << EOF
[libdefaults]
    default_realm = $REALM
    dns_lookup_realm = false
    dns_lookup_kdc = false
    default_tkt_enctypes = aes256-cts-hmac-sha1-96 aes128-cts-hmac-sha1-96 rc4-hmac
    default_tgs_enctypes = aes256-cts-hmac-sha1-96 aes128-cts-hmac-sha1-96 rc4-hmac
    permitted_enctypes = aes256-cts-hmac-sha1-96 aes128-cts-hmac-sha1-96 rc4-hmac

[realms]
    $REALM = {
        kdc = $DC_HOST
        admin_server = $DC_HOST
    }

[domain_realm]
    .$DOMAIN = $REALM
    $DOMAIN = $REALM
EOF

• "Mark as Owned" right-click fails — use Cypher: MATCH (u:User {name:"..."}) SET u.owned=true RETURN u

what is SYSVOL
# SYSVOL = shared folder on every DC, readable by ALL domain users
# Contains Group Policy files pushed to every domain machine
# Path: \\$DC_HOST\SYSVOL\$DOMAIN\Policies\
#
# GPP passwords (cpassword) — admin stored passwords in GPP XML files
# Microsoft published the AES-256 decryption key in their own docs (2012)
# Same key on every Windows installation on the planet
# Patched in MS14-025 but existing files were NEVER deleted
# Still appears constantly in OSCP labs
method 1 — CME automatic (fastest)
try first

# GPP_PASSWORD  DC01  Username: Administrator
# GPP_PASSWORD  DC01  Password: Password123!

# GPP_PASSWORD  DC01  [-] No GPP passwords found
